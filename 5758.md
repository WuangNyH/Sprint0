# [BE] Quy tắc đặt tên & xử lý lỗi API

## 1. Quy tắc đặt tên API

### 1.1. Nguyên tắc chung

* Dùng **RESTful API** chuẩn.
* Tên endpoint sử dụng **danh từ số nhiều**, viết thường, ngăn cách bằng `-` nếu cần.
* Action thể hiện qua **HTTP method**:

  * `GET`   → Lấy dữ liệu
  * `POST`  → Tạo mới
  * `PUT`   → Cập nhật toàn bộ
  * `PATCH` → Cập nhật một phần
  * `DELETE` → Xóa

### 1.2. Cấu trúc endpoint

```
/api/v1/{resource}/{id}/{sub-resource}
```


### 1.3. Quy tắc đặt tên field

* **snake_case** cho database.
* **camelCase** cho JSON response.

Ví dụ:

```json
{
  "departmentId": 1,
  "departmentName": "Công nghệ thông tin"
}
```

## 2. Quy tắc xử lý lỗi API

### 2.1. Cấu trúc lỗi trả về

```json
{
  "timestamp": "2025-09-25T10:15:30Z",
  "code": 400,
  "message": "Tên khoa không được để trống",
  "path": "/api/v1/departments"
}
```

### 2.2. Danh mục lỗi chuẩn

| Code                  | HTTP Status | Ý nghĩa                                     |
| --------------------- | ----------- | ------------------------------------------- |
| `VALIDATION_ERROR`    | 400         | Lỗi validate dữ liệu đầu vào                |
| `NOT_FOUND`           | 404         | Không tìm thấy resource                     |
| `DUPLICATE_ERROR`     | 409         | Dữ liệu trùng lặp (ví dụ: mã SV đã tồn tại) |
| `UNAUTHORIZED`        | 401         | Chưa đăng nhập hoặc token không hợp lệ      |
| `FORBIDDEN`           | 403         | Không có quyền truy cập                     |
| `INTERNAL_ERROR`      | 500         | Lỗi server không xác định                   |
| `SERVICE_UNAVAILABLE` | 503         | Hệ thống tạm ngừng                          |

### 2.3. Quy tắc log & trace lỗi

* Mọi lỗi ghi vào **file log backend** kèm:

  * Thời gian
  * API endpoint
  * Request params
  * UserId (nếu có)
* Gắn **traceId** để theo dõi lỗi xuyên suốt.

---

## 3. Quy tắc versioning API

* Luôn để version trong URL: `/api/v1/...`
* Nếu có thay đổi breaking → nâng version (`/api/v2/...`)

---

## 4. Best Practices

* Luôn trả về **response thống nhất** (success/error).
* Không trả lỗi raw từ DB/Framework → phải mapping sang code chung.
* Tài liệu API được duy trì bằng **Swagger / Postman Collection**.
