# Quy trình code, lập trình và Quy định ghi log task & nội dung cần thực hiện trước khi release

# 🚀 I. Quy trình Code, Lập trình

## 1. Code & Lập trình

### 1.1. Quy tắc code chung

* **Branching model:** sử dụng Gitflow hoặc GitHub Flow

  * `main` → nhánh ổn định (release).
  * `develop` → nhánh phát triển.
  * `feature/*` → nhánh cho từng tính năng.
  * `hotfix/*` → sửa bug khẩn cấp.
* **Code convention:**

  * Backend (Java Spring Boot)
  * Frontend (Vue.js)
* **Commit message:** 

##### 1. **Cấu trúc chung**

```
<type>[optional scope]: <description>
```

**Trong đó:**

* `type`: loại thay đổi (bắt buộc).
* `scope`: phạm vi ảnh hưởng (tùy chọn, ví dụ: user, auth, api, ui...).
* `description`: mô tả ngắn gọn thay đổi (bắt buộc, tối đa ~72 ký tự).


##### 2. **Các loại type thường dùng**

* **feat:** thêm mới tính năng.

  > `feat(auth): add JWT login API`
* **fix:** sửa lỗi.

  > `fix(ui): wrong button color on dark mode`
* **docs:** thay đổi/chỉnh sửa tài liệu.

  > `docs(readme): update setup guide`
* **style:** thay đổi liên quan đến format, convention, không ảnh hưởng logic.

  > `style: format code with prettier`
* **refactor:** chỉnh sửa code (không thêm tính năng, không fix bug).

  > `refactor(api): simplify error handling`
* **perf:** cải thiện hiệu năng.

  > `perf(db): optimize query with index`
* **test:** thêm hoặc chỉnh sửa test.

  > `test(service): add unit test for order service`
* **build:** thay đổi build system hoặc dependency.

  > `build: upgrade spring boot to 3.2.1`
* **ci:** thay đổi CI/CD pipeline.

  > `ci(github-actions): add docker build step`
* **chore:** công việc lặt vặt (không ảnh hưởng source chính).

  > `chore: clean up unused imports`
* **revert:** revert commit trước đó.

  > `revert: feat(auth): add JWT login API`

##### 3. **Quy định thêm**

* **Description**: Viết ở thì hiện tại, ngắn gọn, không viết hoa chữ cái đầu trừ khi cần.

  > ❌ `Fixed bug UI hiển thị` → ✅ `fix(ui): wrong button color`
* **Scope**: nên dùng khi project lớn để phân loại thay đổi.
* **Body (tùy chọn)**: dùng khi commit phức tạp → giải thích chi tiết hơn.

  ```
  feat(order): implement order cancellation API

  - add cancel endpoint in order service
  - update order status enum
  - adjust unit tests
  ```
* **Footer (tùy chọn)**: ghi issue/ticket liên quan.

  ```
  fix(payment): handle timeout error

  close #123
  ```

### 1.2. Code Review

* Mọi feature/bugfix đều phải tạo **Pull Request (PR)**.
* Ít nhất 1–2 reviewer approve trước khi merge.
* Reviewer check:

  * Code clean, dễ đọc.
  * Sử dụng common để không bị lặp logic
  * Unit test đầy đủ.

---

## 2. Build & Test

### 2.1. Backend (Java Spring Boot)

* Dùng **Maven/Gradle** để build.
* Pipeline:

  * `mvn clean install` hoặc `gradle build`.
  * Chạy **JUnit test** + kiểm tra coverage (JaCoCo).
  * SonarQube scan (nếu có) để check quality gate.

### 2.2. Frontend (Vue.js)

* Dùng **npm hoặc yarn**.
* Pipeline:

  * `npm install`
  * `npm run build` (tạo ra thư mục `dist/`).
  * Chạy test: `npm run test` (nếu có unit test với Jest).

# 📘 II. Quy định ghi log task & nội dung cần thực hiện trước khi release

## 1. 🎯 Mục tiêu

* Đảm bảo **tính minh bạch** trong quá trình phát triển.
* Giúp team và PO (Product Owner) **theo dõi đầy đủ** tiến độ, công việc đã hoàn thành, công việc còn tồn đọng.
* Giảm thiểu **rủi ro khi release** bằng cách có đầy đủ log task, checklist rõ ràng.

---

## 2. 📝 Quy định ghi log task

1. **Thông báo qua kênh giao tiếp** (để Team cùng nắm)

2. **Mỗi task phải được ghi nhận đầy đủ trên hệ thống quản lý công việc** (Techkan được team thống nhất).

3. **Log task cần điền đầy đủ các thông tin trong Techkan**

4. **Comment log**: Tất cả thay đổi, vấn đề phát sinh, quyết định kỹ thuật cần được ghi lại trong phần comment.

---

## 3. ✅ Nội dung cần thực hiện trước khi release

Trước khi phát hành (release), team cần thực hiện và ghi log theo các hạng mục sau:

### 3.1. Kiểm tra Task & User Story

* Đảm bảo **100% task trong Sprint Backlog** đã chuyển sang trạng thái `Done`.
* Kiểm tra lại **Definition of Done (DoD)** cho từng User Story:

  * Code đã được merge vào branch chính (main).
  * Code đã được review (Code Review xong).
  * Unit test & Integration test đạt yêu cầu.
  * Không còn bug blocker/critical.
  * Document (nếu có) đã được cập nhật.

### 3.2. Kiểm thử & chất lượng

* ✅ Regression test trên môi trường local.
* ✅ Tài liệu test case / kết quả test được log lại.
* ✅ Đảm bảo hệ thống build & pipeline CI/CD chạy thành công.

### 3.3. Checklist Release

* 📌 Ghi lại **phiên bản release** (version, tag Git).
* 📌 Ghi log **các tính năng mới** (new features).
* 📌 Ghi log **bug fix** đã hoàn thành.
* 📌 Ghi log **công việc còn tồn đọng** (nếu có, chuyển sang backlog).
* 📌 Chuẩn bị **Release Note** cho PO/Stakeholder.

---

### 🔹 Bug Fix

### 🔹 Known Issues

* [x] Pipeline CI/CD pass ✅

---

## 5. 📌 Lưu ý

* Tất cả thành viên Scrum Team đều có trách nhiệm ghi log chính xác.
* Scrum Master có trách nhiệm kiểm tra checklist trước khi release.
* PO cần xác nhận nội dung release note trước khi phát hành chính thức.
